# Progressive render admission

Approved on 2026-09-15 (devbrain gffx D297). This changes the forecast used to admit a qualification worker; it does not accelerate rendering or relax correctness.

For one matching execution profile, select the two largest passed complete-frame sizes below the target. Take the slower measured seconds per pixel, multiply by target pixels and by two, then add 30 seconds. A prediction is never a completed measurement. All supplied anchors must pass validation, including anchors that are not selected.

`python -m tools.deferred_progressive_probe --execution resident|stream` wraps the existing probe. Supply the original `--calibration32` and `--calibration64` arguments plus repeated `--anchor REPORT SHA256` pairs. All other original probe options are forwarded. The wrapper and policy hashes are recorded separately from the execution driver. During qualification, visual inspection found a pre-existing width/height reversal in both probe camera calls. Those calls now use explicit dimension keywords, and output shapes are checked before success. The driver hashes therefore changed: fresh matching-driver anchors are required. The old square evidence remains historical; two wrongly shaped1080p reports and an unpublished gallery are explicitly invalidated in admission45-1080-invalidation1.json. The child receipt retains the original 32/64 forecast and the selected progressive anchors.

Reports and every saved colour/mask array are hash-checked, including exact declared extent, float64 storage and byte count. Anchors must match the installed wheel, execution driver, scene, helper sources, device, dtype, material, softness, differentiation profile, outputs, ownership profile and material group limits. Failed, refused, incomplete, duplicate-sized, nonprior or mismatched evidence is rejected. Duration must be positive and finite. Original startup-anchor checks also still run.

Admission still uses the original memory planning and remaining cooperative deadline. CPU workspace remains 64 MiB per window, CPU whole-worker allowance 1 GiB and CUDA host allowance 2 GiB. CUDA uses the approved available-VRAM headroom policy and whole-frame-first selection. The cooperative deadline remains 120 seconds and watchdog 180 seconds. Heavy workers run serially with one thread. Four-point partials, 128-point grouped dispatch, 1,024 point/light pairs, all numerical tolerances and exact accumulation requirements are unchanged.

The focused tests preserve a missing-implementation red and a parent receipt-overwrite red before the green result. Live preflight also rejects a deliberately incorrect anchor hash without rendering. Scale reports remain finite single-job measurements, not sustained-throughput claims; independent accuracy, larger gradients and presentation acceptance remain separate gates.
