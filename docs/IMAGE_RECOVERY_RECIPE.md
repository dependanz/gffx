# Full synthetic image-recovery recipe v0.1

Status: bounded CPU recipe qualified 2026-09-10 on exact source14 wheel; the
prospective recipe below was preserved before execution and was not retuned. This
extends the existing translation/opacity example without altering its source or
results. Source: `tests/python/test_image_full_recovery.py`. CI-07 means gffx is
ready to start consumer development, not that a consumer application exists.

## Fixed data and visible equations

The canvas is 32×32 CPU float64. Two asymmetric first-party coloured layers are
generated by scalar loops, with no random seed, file, asset or model dependency.
The lower diamond-shaped layer is locked; the upper notched ellipse has a fixed
source-space soft mask. Source textures are straight sRGB RGBA; the opaque
background and output are explicitly linear-premultiplied RGBA.

The public recipe performs explicit RGB decoding and premultiplication, exposure
and brightness, source-space mask/opacity, separable Gaussian blur with fixed
radius 2, inverse-sampled affine warp with transparent borders, then ordered
alpha-over of locked lower and moving upper layers above the canvas. There is no
implicit output encoding, minification filter or clipping. Reconstruction is
optional in the library contract and is not inserted into this 32×32 recipe.

`scalar_reference` implements the same equations with Python loops and `math`,
never gffx operations or shared production/reference helpers. It independently
decodes sRGB, normalizes five Gaussian weights, applies horizontal then vertical
transparent convolution, constructs/inverts the affine map at pixel centres,
bilinearly gathers four neighbours and composites in the declared order. The
target is fixed before optimization and is never copied from a production result.

## Prospective perturbations and optimizer

|---|---:|---:|---|
| x translation, pixels | 0.37 | 0.62 | (-1, 1) |

| x scale | 1.035 | 1.012 | (0.9, 1.1) |
| y scale | 0.965 | 0.988 | (0.9, 1.1) |
| Opacity | 0.77 | 0.68 | (0.5, 0.95) |
| Exposure, stops | 0.18 | -0.04 | (-0.5, 0.5) |
| Brightness, linear units | 0.012 | -0.006 | (-0.05, 0.05) |
| Gaussian sigma, pixels | 0.85 | 1.05 | (0.6, 1.4) |

Pivot is fixed at (14.3, 15.7) pixels. Physical parameters are centre plus range
times tanh of unconstrained optimizer variables, initialized by the exact inverse
map. This states a local recovery basin; it does not reveal target parameters to
an objective or force their recovery. No bound changes follow from a failed run.

Use PyTorch LBFGS: learning rate 1, maximum 60 iterations, maximum 100 closure
evaluations, history size 9, strong-Wolfe line search, gradient tolerance 1e-12
and change tolerance 1e-15. A separate closure counter raises on evaluation 101,
even if an internal line search would otherwise exceed the declared maximum.
Run twice from the same initial state with newly created optimizers and graphs.

## Required results, not observations

- A separate 5×7 stage fixture runs first, with a fixed local pivot (3.1, 2.2).
  Compare intake, locked intake, adjustment, mask, blur, matrix, warp and composite
  individually against scalar equations at atol=2e-12, rtol=2e-12. Crops deliberately
  contain nonzero asymmetric foreground/lower-layer content.
- Independent target and public output agree at float64 atol=2e-12, rtol=2e-12.
- All nine initial physical-parameter objective derivatives agree with independent
  scalar central differences at both eps=1e-6 and eps=5e-7, using adopted full-chain
  atol=5e-5, rtol=5e-4. Require every analytical derivative to be finite and
  nonzero. At both difference scales, compare base and each perturbed inverse-map
  floor-cell indices wherever either sample touches nonzero blurred-alpha support;
  they must remain identical. Record sampling-knot distance, maximum coordinate
  displacement, gradient values and absolute errors. These explicit cell checks
  qualify the smooth local branch; a recorded margin alone would not. Do not
  retune perturbations or tolerances after seeing a result.
- Objective is mean squared error over all 32×32×4 linear-premultiplied channels.
  Final MSE, evaluated on a fresh graph after optimization, is at most 1% of initial
  MSE. Every optimizer closure requires finite loss and gradients.
- Fixed textures, mask, locked layer, background and target retain exact bytes and
  tensor version counters. Check versions at every closure and bytes before/after
  each repeated solve. No old graph or output is used as an objective cache.
- Repeated solves produce byte-identical parameters/output and identical recorded
  losses/evaluation counts. Record absolute error for every physical parameter;
  image agreement does not establish a unique solution, especially for correlated
  opacity/exposure/brightness or scale/blur effects.

## Execution envelope and evidence boundary

No run is authorized by this document. Request the coordinator's serial worker
lease and exact installed-wheel identity. Use one CPU thread, 1 GiB whole-process
host cap, 120-second cooperative and 180-second watchdog limits. No CUDA acceptance
or performance claim follows from this CPU recipe.

The derivative test uses 38 scalar reference evaluations (target, initial margin,
and 36 differences) and two public evaluations. The tiny stage test adds one
scalar and one public evaluation. The recovery test uses one scalar target and at
most 204 public evaluations: two solves with 100 closures plus initial/final
evaluations each. The complete three-test recipe therefore permits 40 scalar and
at most 207 public evaluations; sampling-cell checks reuse those scalar calls.
Both repeated solves share one 120-second cooperative deadline checked before and
after each closure/backward, and after fresh final evaluation; they do not each
receive a separate 120-second allowance. The worker's 180-second watchdog remains.
No full image Jacobian is materialized: gradients are nine scalar parameters;
LBFGS retains at most nine history pairs. Five 32×32-class fixed tensors and
bounded radius-2 intermediates are small relative to the process limit; measured
whole-worker peak/time remain required and must not be inferred from tensor sizes.

Each test has an authored purpose/method docstring. Dashboard routing, generated
initial/target/recovered/residual visual artifacts and actual visual review remain
separate coordinator-owned work. No document revisions, undo/redo, cancellation
transactions, consumer packages or real design recovery are tested here.
